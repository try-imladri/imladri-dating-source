# Imladri Personal on Cloudflare

Run these commands from `cloudflare/` with Node 24, Corepack, and Docker available. The Worker serves the React build and proxies `/api` on the same origin. Clerk bearer tokens, cookies, idempotency keys and signed webhook bytes pass through. The proxy disables caching for API responses.

```sh
npm ci
npm run build:assets
npm test
npx wrangler deploy --dry-run
```

## Preview

`npx wrangler deploy` updates the independent `imladri-personal-preview` workers.dev site. Its API is the Render pilot. It has no production route or cron trigger. To exercise the edge locally, start FastAPI and use `npx wrangler dev --local --var API_ORIGIN:http://127.0.0.1:8187`.

## Private live API and readiness

1. The private `imladri-personal-api` Worker requires Workers Paid. Its Linux container runs the FastAPI app, using the `imladri_personal_live` MongoDB database. Create a database user restricted to that database. The image accepts settings only at runtime. Its Docker build context contains the Python sources, pinned requirements, catalog, seed media and startup script. [Cloudflare Container pricing](https://developers.cloudflare.com/containers/platform/pricing/)
2. Prepare a protected JSON object outside the build context with the live `MONGO_URL`, `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `CLERK_WEBHOOK_SIGNING_SECRET`, `ADMIN_EMAIL`, `DEEPSEEK_API_KEY`, `OPS_CHECK_SECRET`, `AI_MEMBER_HOURLY_CALL_LIMIT`, `AI_DAILY_TOKEN_LIMIT` and `PERSONAL_BILLING_MODE`. Use `disabled` while payments are unavailable. Enabling billing requires the live `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PORTAL_CONFIGURATION` and the $12 monthly catalog price. The operations check requires an explicit portal configuration. `CLERK_AUTHORIZED_PARTIES` is optional. Set `CLERK_PROXY_URL` only for a Clerk deployment using the relay.
3. Deploy with `npx wrangler deploy --config wrangler.api.jsonc --secrets-file <protected.json>`. This uploads encrypted Worker bindings in the same version as the private API. The API Worker has no public hostname. Additional secret rotations can use `wrangler secret bulk --config wrangler.api.jsonc` with JSON on stdin. The public readiness facade is a separate deployment, `npx wrangler deploy --env candidate --secrets-file <edge-secret.json>`, with only the matching operations and standby origin secrets described below. It serves the frontend and a restricted set of live reads plus the protected operations check. The candidate has no zone routes or cron trigger.
4. When the database needs an egress observation, add `--var CF_DIAG_EGRESS_ON_START:true` to the private deployment before the first cold start. Send a bearer-authenticated `POST /api/ops/check` on the candidate. The container's startup script prints one `imladri_container_egress_ipv4` entry to private Cloudflare container logs before FastAPI needs Atlas. Read the entry in Workers Observability. Add the narrow approved source address to Atlas and verify actual catalog reads. The observed HTTPS egress address can change with placement, and Atlas connections use their own TCP flow. For a stable restricted deployment, provide fixed egress or a private network path, or maintain a dedicated reachable production Render origin. Redeploy the private API without the diagnostic flag after verification. [Cloudflare container placement and logs](https://developers.cloudflare.com/containers/faq/) · [Container network behavior](https://developers.cloudflare.com/containers/configuration/outbound-traffic/) · [Atlas access lists](https://www.mongodb.com/docs/atlas/security/add-ip-address-to-list/)
5. Verify `/api/`, `/api/public/archetypes`, the public Clerk configuration and expected unauthenticated `/api/me` response on the candidate. Verify the authenticated operations check using the backend secret. Check the protected endpoint denies unauthenticated traffic. Direct signed-in Clerk and payment flows need their live domain configurations.

## Cutover and rollback

The production API container and its Render standby share one dedicated DeepSeek key. Set `DEEPSEEK_API_KEY`, `DEEPSEEK_PRODUCTION_KEY_NAME` (the exact label in DeepSeek Usage), and `DEEPSEEK_PRODUCTION_KEY_ID` (the first 24 lowercase hexadecimal characters of the stripped key’s UTF-8 SHA-256 digest) together on those two services. Preview, development and offline content jobs use separate credentials. Rotate the production bindings through the secret stores so editorial tools that load local `.env` files cannot use the production key.

The production and container environments target the same Worker, bindings and routes. Publish with `npx wrangler deploy --env production --secrets-file <edge-secret.json>` after readiness passes. The edge JSON contains `OPS_CHECK_SECRET` and `RENDER_ORIGIN_SECRET` matching the standby. The operations secret also matches the private API. Candidate automatic routing uses these same two edge bindings. Production's quarter-hourly trigger posts the protected check and reports only the HTTP status on failure. [Cloudflare Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/)

A new private API Worker release gracefully restarts its previous container on first use so updated images and secret bindings take effect. The live database stays in Atlas. During egress provisioning only, the protected `POST /api/ops/check` also accepts `X-Imladri-Egress-Diagnostic: 1` to return a measured IPv4 from the running Linux process before database readiness. With diagnostics disabled, this request returns 404. A healthy `GET /api/ready` plus real catalog reads verify MongoDB connectivity after a restart. [Durable Object container lifecycle](https://developers.cloudflare.com/containers/api/durable-object-container/)

Production overlays `imladri.com/*` and `www.imladri.com/*` on the existing proxied records. The Worker responds to www with a path- and query-preserving 308 to the apex. Keep the previous Pages project and its DNS records available. Removing the two Personal Worker routes restores that origin. A subsequent production deploy will reapply the overlays. [Cloudflare Worker routes](https://developers.cloudflare.com/workers/configuration/routing/routes/)

Set the live Clerk origins, Stripe checkout/portal return URL and signed webhook endpoints for the apex. The Clerk path is `/api/clerk/webhook` and the Stripe path is `/api/stripe/webhook`. Each webhook signing secret belongs to its specific endpoint and provider mode. Confirm signed delivery and retries to the live endpoint before retiring any previous endpoint. Keep all live API instances on the same live database. Seed an empty database once before bringing multiple origins online.

### Enabling Personal Plus

1. Keep `PERSONAL_BILLING_MODE=disabled` on both `imladri-personal-api` (the private Cloudflare Worker) and `imladri-personal-live-api` (the protected Render standby) while staging. In the Imladri live Stripe account, verify the active licensed monthly USD 12 price with lookup key `imladri_plus_100_monthly_usd12`. From the repository root run `python scripts/setup_stripe_live_price.py --account <expected-account-id>` with the live key supplied through the process environment. If the price is missing, the separate `--create-live` operation creates the product and price idempotently. The app grants 100 replies for the paid period. New live products receive Stripe tax code `txcd_10105001` for cloud-based AI services for personal use. The release check flags an existing product with a missing or different category for review. Stripe lists this category for both Stripe Tax and Managed Payments. [Stripe product tax codes](https://docs.stripe.com/tax/tax-codes) · [Managed Payments eligibility](https://docs.stripe.com/payments/managed-payments/eligibility)
2. Configure a live portal with cancellation at the end of the billing period (`at_period_end`), payment method updates and invoice history to match the pilot. Confirm the portal displays the effective date when reviewing the live configuration. Register the single live Stripe destination at `https://imladri.com/api/stripe/webhook` for `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `checkout.session.expired`, `invoice.paid`, `customer.subscription.updated` and `customer.subscription.deleted`. The handler also accepts `invoice.payment_succeeded` as a renewal alias. The Clerk `user.deleted` destination remains `https://imladri.com/api/clerk/webhook` with its own signing secret.
3. Supply the live `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET` for that destination, and `STRIPE_PORTAL_CONFIGURATION` to the verification process. Run `python scripts/setup_stripe_live_price.py --account <expected-account-id> --verify-release`. This reads the account’s charge capability, price, product, portal and webhook settings. The signing secret value is available from the live endpoint in Stripe. [Stripe webhook endpoints](https://docs.stripe.com/api/webhook_endpoints/object)
4. Stage those three Stripe settings, the selected `STRIPE_CHECKOUT_MODE`, and `PERSONAL_BILLING_MODE=disabled` on both API services. From `cloudflare/`, run `npx wrangler secret bulk <protected-billing.json> --config wrangler.api.jsonc` using a protected file outside the checkout. Wrangler preserves other bindings. In Render open **imladri-personal-live-api → Environment**, set the same values, and **Save and deploy**. Keep `PUBLIC_APP_URL=https://imladri.com` on both. After staging, confirm genuine signed delivery in Stripe Workbench when available. The public edge needs only its existing origin and operations secrets. The sandbox pilot has its own price, keys, portal and webhook. [Cloudflare Worker secrets](https://developers.cloudflare.com/workers/configuration/secrets/) · [Render environment variables](https://render.com/docs/configure-environment-variables)
5. Inspect the live account’s customer-facing receipt, hosted subscription invoice and invoice PDF for the checkout path Personal will use. Stripe’s official live-account previews or existing documents generated with those settings can supply this evidence before the first sale. Confirm each omits the owner’s personal phone number and street address, including issuer and support fields. Imladri selected `STRIPE_CHECKOUT_MODE=managed` for launch. Verify a customer-facing Link receipt for this live Managed Payments account as part of the review. Stripe sends that receipt separately from standard Stripe Billing receipts. With `standard`, Imladri sells the subscription directly and Checkout requires Stripe automatic tax and the customer’s billing address. Set the same explicit choice on the private Worker and Render before opening checkout. The default `auto` preserves the pilot’s managed-first behavior with direct automatic tax as a fallback. Keep public checkout paused until the applicable live templates have been reviewed. [Stripe receipts](https://docs.stripe.com/receipts) · [Invoice customization](https://docs.stripe.com/invoicing/customize)
6. After that review, set only `PERSONAL_BILLING_MODE=enabled` on both origins and deploy the environment changes. Check `GET /api/ready` and the authenticated `POST /api/ops/check` on the private service binding and separately on the Render standby with its origin header. Both operations checks must return true for `stripe` and `stripe_invoices`. At the apex, confirm a newly signed-in member has zero replies and sees the single $12 monthly offer for 100 replies with no trial. Keep Stripe delivery results and customer privacy evidence in the account’s private release records.

To pause sales, redeploy `PERSONAL_BILLING_MODE=disabled` on both API services. This pauses new Checkout and portal sessions. Keep the live Stripe secrets and webhook destination in place for existing renewals, cancellations and account closure. Previously issued Checkout session URLs may remain payable until they expire. Before changing checkout mode, expire the previous mode’s open sessions in Stripe or wait for expiry. Retries for an outstanding attempt from another mode wait for expiration. Unmarked attempts from earlier releases use the default `auto` policy. Stripe continues existing subscriptions according to their current terms.

For backend failover, provision `imladri-personal-live-api` on Render with the same live database, keys and canonical URL. Give Render and the production edge a separate matching `RENDER_ORIGIN_SECRET`. The configured automatic mode runs a credential-free, time-limited readiness check before selecting the private Container or this exact HTTPS standby. The Worker replaces inbound `X-Imladri-Origin` only for the standby. It caches a healthy routing decision for five seconds or a failed decision for fifteen seconds. Browser API requests and scheduled checks each reach their selected backend once. To pin to the verified standby, deploy with `--var RENDER_FAILOVER_MODE:standby`. An ordinary deployment restores automatic selection.

The Render preview and production standby each run on one Starter instance to stay available between requests. When routing to Render, the public Worker first checks the service with a two-and-a-half-second readiness deadline. A sleeping origin receives only the readiness request. The edge returns a temporary response with a three-second retry delay if the service is still starting. Browser reads retry for up to two minutes; a write is only forwarded once the selected origin is ready. Public plan prices are served directly by Cloudflare from the same catalog as billing. Registration status and member data come from the current backend.

The standby can maintain narrowly scoped Atlas ingress using a dedicated high-entropy `CF_EGRESS_PROBE_SECRET` on Render and the private API Worker. Keep this credential out of the Linux application. Render uses it for a bodyless `POST /api/ops/container-egress` on the candidate hostname, which returns the running container's current IPv4 before Mongo is reachable. The apex conceals this path. Failed primary readiness requests trigger an independent, authenticated standby repair in the background, limited to one attempt per two minutes per edge isolate. The midnight UTC cron slot also requests maintenance. The Linux process waits for Atlas before starting FastAPI to preserve its observed egress while access is restored.
